# Jezper.se V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a zero-cost, statically-generated personal site at `jezper.se` with notes + long-form writing, music archive, projects, /now, /about, /elsewhere, three RSS feeds, and an Obsidian-based publishing workflow that deploys via Cloudflare Pages on `git push`.

**Architecture:** Astro with Markdown content collections. Two writeable collections (`notes`, `writing`) and prose pages (`about`, `now`) as Markdown. Curatorial pages (`music`, `projects`, `elsewhere`) are data-driven from YAML. Light-canonical theme with a dark toggle. Self-hosted fonts. Three RSS feeds. No backend, no database, no runtime. Repo doubles as an Obsidian vault using Obsidian Git for auto-sync.

**Tech Stack:** Astro 4.x, TypeScript (strict), Zod (via Astro Content), `@astrojs/rss`, `@astrojs/sitemap`, `remark-wiki-link`, Vitest (utilities), Playwright (smoke tests), Cloudflare Pages (host), Obsidian + Templater + Obsidian Git (authoring).

## Visual Direction (locked from brainstorm)

Hybrid of "Reading Room" (D1) + "Field Notebook" (D3) bones with one move from "Late Session" (D2).

- **Display face:** Migra (Pangram Pangram, free) — used 1–3× per page
- **Body face:** Newsreader (Production Type, free, Google Fonts available — but self-hosted)
- **UI face:** Satoshi (Pangram Pangram, free via Fontshare) — used for nav, footer, kickers, section markers (token: `--font-ui`)
- **Mono face:** JetBrains Mono (free, self-hosted)
- **Light tokens:** `--paper #F7F4EE`, `--ink #1A1815`, `--ink-muted #6E6A62`, `--ink-faint #B8B3A9`, `--rule #E5DFD3`, `--surface-2 #EFEAE0`, `--accent #7A1F1F` (Falun red), `--accent-hover #5A1414`, `--selection #F0D5C8`

Product roadmaps promise certainty they cannot deliver. After a decade of trying — at small companies, at Mecenat, in side projects — I think the honest version of a roadmap is closer to a *commitment ledger*.

## The problem with roadmaps

A roadmap, in its conventional form, is a Gantt chart of beliefs. It tells stakeholders that **Feature X** ships in **Month Y**. The first part is approximately right. The second is theatre.

## A commitment ledger instead

Three things are useful to share with stakeholders:

1. What we have committed to
2. What we are betting on but not committed to
3. What we are deliberately *not* doing

Each lives at a different time horizon. Each has a different epistemic status. None is a Gantt chart.

// src/lib/readingTime.ts
const WORDS_PER_MINUTE = 200;

export function readingTime(text: string): number {
  const stripped = text
    .replace(/!\[.*?\]\(.*?\)/g, '')
    .replace(/\[(.*?)\]\(.*?\)/g, '$1')
    .replace(/[#*_>`~-]+/g, ' ')
    .replace(/<[^>]+>/g, ' ');
  const words = stripped.trim().split(/\s+/).filter(Boolean).length;
  return Math.max(1, Math.ceil(words / WORDS_PER_MINUTE));
}

const longFormatter = new Intl.DateTimeFormat('en-US', {
  year: 'numeric', month: 'long', day: 'numeric', timeZone: 'UTC',
});

export function formatDate(d: Date): string {
  return longFormatter.format(d);
}

export function formatDateShort(d: Date): string {
  const y = d.getUTCFullYear();
  const m = String(d.getUTCMonth() + 1).padStart(2, '0');
  const day = String(d.getUTCDate()).padStart(2, '0');
  return `${y}-${m}-${day}`;
}

export function formatIsoDate(d: Date): string {

import type { CollectionEntry } from 'astro:content';

export function rssDescription(entry: CollectionEntry<'notes' | 'writing'>): string {
  if (entry.data.description) return entry.data.description;
  const firstPara = entry.body.split('\n\n').find(p => p.trim().length > 0) ?? '';
  return firstPara.slice(0, 280);
}

export function entryUrl(entry: CollectionEntry<'notes'> | CollectionEntry<'writing'>, site: URL): string {
  const path = entry.collection === 'notes' ? `/notes/${entry.slug}/` : `/writing/${entry.slug}/`;
  return new URL(path, site).toString();
}

## Publishing workflow (Obsidian)

The repo doubles as an Obsidian vault. To set it up:

1. Clone the repo to your machine.
2. In Obsidian: **Open folder as vault** → choose the cloned repo's root.
3. Install three plugins via **Settings → Community plugins**:
   - **Obsidian Git** — for auto-commit and push
   - **Templater** — for new-note frontmatter templates
   - (Optional) **Linter** — keeps frontmatter tidy
4. Configure **Obsidian Git**:
   - **Vault backup interval (minutes):** `5`
   - **Auto pull on startup:** `on`
   - **Commit message:** `note: {{date}}` or `update`
   - **Sync method:** commit-and-sync
5. Configure **Templater**:
   - Template folder location: `.templates`
   - Map "Cmd+N" or a quick action to insert `new-note.md` or `new-article.md`

### Day-to-day

1. Open Obsidian.
2. Create a new note in `src/content/notes/` (Templater pre-fills frontmatter).
3. Write. Save (Obsidian autosaves).
4. Within ~5 min, Obsidian Git auto-commits and pushes to GitHub.
5. Cloudflare Pages picks up the push and rebuilds. Live at jezper.se in ~30–60 s.

### Long-form

Same flow, but in `src/content/writing/`. The Templater "new article" template defaults to `draft: true` — flip to `draft: false` when ready to publish.

### Wikilinks and embeds

Obsidian's `[[wikilink]]` syntax is supported via `remark-wiki-link`. Resolve note-to-note references naturally — they get rewritten to `/notes/<slug>/` at build time.
